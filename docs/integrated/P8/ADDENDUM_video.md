# P8 추가 — 동영상 입력 (import 확장, 사용자 제공 2026-10-22)

사용자가 Grok 이미지→동영상으로 SD 기사 공격 동작 6초(448×672, 24fps, 145프레임)를 만들었다. 기획 세션 시제품으로 11프레임을 뽑아 키 60px로 정리한 결과: samples/grok_attack_60_3x.png. 동작(준비→내려베기→회수)이 실제로 읽히고 얼굴·머리·갑옷이 프레임 사이에서 유지된다. → 공격·피격·필살기처럼 "움직임"이 중요한 동작은 동영상이 정지 이미지보다 유리하다.

## 확인된 문제와 처리 (import 1~8단계 앞에 붙는 전처리)
1. **가짜 체크무늬 배경이 그림에 박혀 있다**(투명 아님, #d4d4d4·#fcfcfc). 처리: 채도 낮고(최대−최소 ≤ 14) 밝은(최소 ≥ 196) 픽셀 중 **이미지 가장자리와 연결된 영역만** 배경으로 제거. 캐릭터 안쪽 흰 천·은색 갑옷은 외곽선에 둘러싸여 있어 보존된다. Spec `background: "auto" | "checker" | "chroma:#00ff00"`.
2. **카메라가 움직인다**: 발 위치가 574→590px로 이동, 장면 중 줌 변화. 처리: 프레임마다 "몸 키"(무기·이펙트 제외 — 가장 큰 연결 성분의 머리 꼭대기~발)를 재서 배율을 프레임별로 보정, 발 중앙 정렬. 몸 키 변화가 ±8%를 넘는 프레임은 `import.camera-zoom` 경고.
3. **무기가 화면 밖으로 잘린다**(일부 프레임 y=0 또는 x=0 접촉). 기존 `import.clipped` 경고로 처리, 해당 프레임은 후보에서 제외 가능.
4. **이펙트가 섞인다**(하늘색 베기 궤적·반짝임). 처리: 고채도 하늘색·흰색 계열 중 캐릭터 본체 성분과 떨어진 픽셀을 `fx` 레이어로 분리해 별도 시트로 출력(옵션). 기본은 제거.
5. **프레임 고르기**: 145장 중 동작 키프레임 선택. `layout`에 `"video": {"fps": 24, "pick": [1,37,55,85,103,109,113,117,121,133,145]}` 수동 지정 + `--probe`가 "몸 실루엣 변화량이 큰 프레임" 상위 N개를 후보로 제안.

## CLI
- `forge import <spec>`가 `.mp4` 입력을 받으면 ffmpeg로 프레임 추출 → 위 전처리 → 기존 1~8단계.
- ffmpeg는 선택 외부 도구(있으면 쓰고 없으면 "PNG 프레임 폴더를 입력하라" 오류). 저장소 의존성에 넣지 않는다. 런타임 의존성 추가 금지 규칙 유지.

## 수락
- 합성 테스트: 체크무늬 배경 + 흰 천 내부 영역 보존, 프레임별 줌 보정(같은 스프라이트를 0.9·1.0·1.1배로 놓은 3프레임 → 출력 몸 키 동일).
- 사용자 영상(samples에는 contact만 있음, 원본 mp4는 사용자가 로컬 경로로 제공)으로 위 11프레임 import → 시트 + fx 분리 시트 + 경고 목록.

# P2 — spec 스키마 + 정지 프레임 렌더러

## 목표
Spec JSON 하나로 **기본 포즈 1프레임**을 규칙에 맞는 도트로 렌더링한다(애니메이션은 P4).

## 읽을 것
- ARCHITECTURE §6, §7, §8.1(뼈 이름·구조만)
- rules: `shade`, `outline`, `cleanup`

## 작업 순서
1. `spec/src/schemas.ts`: zod 스키마 `Bible`, `Rules`, `Spec`, `Rig`(뼈 정의만), `PartShape`(discriminated union: line|rect|ellipse|capsule|poly|mask) + `z.infer` 타입 export. Bible은 `view`·`directions`·`sizeClasses`(자유 키 맵)·같은 키의 `colorBudget`, Spec은 `kind`, Rig 뼈는 `depthLayer`(§7, §8.1)
   - `kind ≠ "character"` 또는 `view ≠ "side"`는 `ForgeError("spec.kind-not-implemented")` / `ForgeError("bible.view-not-implemented")`
2. `spec/src/refs.ts`: 참조 무결성 검사(재질∈바이블, bone∈리그, sizeClass∈sizeClasses) → 오류 목록
3. `data/rigs/humanoid-side-v1.rig.json`: §8.1 뼈대, 키 30px 기준 길이·피벗·restAngle, depthLayer, drawOrder
4. `rig/src/transform.ts`: 뼈 계층 → 월드 위치/각도(정수 스냅). 이 단계는 rest pose만 사용
5. `render/src/zone.ts`: ZoneBuffer 생성, 파츠 마스크를 depth 비교로 기록
6. `render/src/shade.ts`: 법선·광원 → shade 양자화, `depthLayer = back` −1단계 (`// rule: form.depth-cue`). 뼈 이름 참조 금지
7. `render/src/resolve.ts`: material+shade → 팔레트 인덱스
8. `render/src/outline.ts`: selout / dark / 내부선
9. `render/src/render-frame.ts`: §6 단계 1~9 순서로 조립. 각 단계 결과를 `debug` 옵션 시 반환(테스트용)
10. `cli`: `forge validate <spec>`, `forge render <spec>`(rest pose 1프레임 → `out/<id>/frames/rest.png`)
11. 샘플 Spec 3개 작성: `data/specs/sample/warrior.spec.json`, `rogue.spec.json`, `mage.spec.json` — 역할 대표색(`roleColorKey`)과 실루엣 차이가 드러나게(전사: 넓은 어깨·검, 도적: 후드·단검·좁은 몸, 마법사: 긴 로브·지팡이)

## 핵심 테스트
- 단색 원 하나 Spec → 골든 해시
- 광원 방향을 반대로 하면 밝은 면이 좌우 반전
- 외곽선 모드 3종 각각 골든
- 팔레트 밖 인덱스 생성 시 assert 발생(개발 모드)
- 샘플 Spec 3개 validate 통과

## 범위 밖
애니메이션·보간, QA 점수, 패킹.

## 수락 기준
```
pnpm build && pnpm test -- --reporter=dot
pnpm forge validate data/specs/sample/rogue.spec.json
pnpm forge render data/specs/sample/rogue.spec.json
```
세 캐릭터 rest 프레임을 임시로 한 장에 이어 붙인 PNG(4배)를 만들어 **1장만** Read, 실루엣 구분·색감에 대해 progress에 2줄 평가. 개선은 Spec 수정으로만(렌더러 수치 변경은 rules 파일에서).

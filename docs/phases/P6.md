# P6 — 클로드 코드 스킬 + 레퍼런스 분석기

## 목표
"기획서의 ○○ 캐릭터를 개발에 적용해줘" 한 문장으로 Spec 작성 → build → QA 루프 → apply까지 자동 수행.

## 읽을 것
- ARCHITECTURE §1, §7.2, §11
- 지금까지 만든 `data/specs/dungeon/*.spec.json` 중 1개 (예시로)

## 작업 순서
1. `skills/forge/SKILL.md` 작성 (200줄 이내). 내용:
   - **트리거**: 캐릭터·몬스터 스프라이트 생성·수정·적용 요청
   - **절차**
     1. 기획서에서 해당 캐릭터 절만 Grep으로 찾아 읽기(직업, 무기, 성격, 크기, 필요한 애니)
     2. 같은 sizeClass의 기존 Spec 1개를 템플릿으로 복사 → 파츠·재질·비율 수정 (바이블 재질만 사용, 새 색 필요 시 사용자에게 바이블 추가 제안)
     3. `forge build` → JSON 요약 확인
     4. 실패 시 `qa.json`의 failed만 보고 Spec 수정. 시각 판단이 필요할 때만 `sheet.png` 1장 Read
     5. 최대 3회 반복 후에도 불합격이면 중단하고 실패 항목·가설 보고
     6. 통과 시 `forge build-all <project>`로 교차 검사(실루엣·스케일) → `forge apply`
   - **금지**: 픽셀 직접 편집, 렌더러 코드 수정, rules 수치 임의 변경(제안만)
   - **보고 형식**: 캐릭터 id / 점수 / 반복 횟수 / 적용 경로 (4줄)
2. 레퍼런스 분석기 `forge ref analyze <png> --source <url> --license <id>`:
   - 측정: 캔버스·실루엣 키(px), 고유 색 수, 색 군집 → 추정 램프(명도순), 램프별 hue 이동량, 외곽선 유형(검정/셀아웃/없음) 추정, 머리·몸 비율
   - 출력: `data/refs/<id>.ref.json`만 저장. **원본 이미지는 저장소에 복사하지 않는다**
   - 라이선스 필드 필수(누락 시 exit 1)
3. `forge ref compare <spec> <ref>`: Spec 빌드 결과와 레퍼런스 측정값 차이를 표 JSON으로 → 규칙·Spec 조정 근거

## 수락 기준
```
pnpm build && pnpm test -- --reporter=dot
pnpm forge ref analyze <임의의 CC0 png> --source <url> --license CC0
```
그리고 신규 직업 1종(예: 성직자)을 SKILL.md 절차만 따라 0에서 apply까지 수행, 반복 횟수·토큰 체감을 progress에 기록.

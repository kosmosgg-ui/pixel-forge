# P3 — QA + 컨택트 시트 + build/캐시

## 목표
"사람 눈 대신 코드가 먼저 거른다." 모든 산출물은 QA를 통과해야 승격된다.

## 읽을 것
- ARCHITECTURE §9, §11(validate/render/qa/build/build-all/캐시)
- rules: `qa`, `colorBudget`

## 작업 순서
1. `qa/src/types.ts`: `Check = { id, required, pass, value, threshold, where?: [x,y][] }`, `Report = { id, pass, score, checks, sheet: {path?, legend} }`
2. 단일 캐릭터 검사(각 파일 1개, 테스트 동반): `palette.conformance`, `alpha.binary`, `color.budget`, `bounds.canvas`, `cleanup.orphans`, `cleanup.banding`, `read.contrast`
   - `baseline.stable`, `anim.flicker`는 함수만 만들고 프레임 1장일 땐 자동 통과(P4에서 실사용)
3. 교차 검사: `form.silhouette`(실루엣 IoU, 발밑 정렬 후), `scale.consistency`
4. `qa/src/sheet.ts`: 컨택트 시트 IndexedRaster 생성(§9) + 실패 위치 빨간 테두리(전용 디버그 색은 QA 팔레트 확장으로, 산출물 팔레트와 분리)
5. `cli/src/cache.ts`: 해시 키 계산(§11), `.forge-cache/<hash>/` 저장·조회
6. `cli`: `forge qa`, `forge build`, `forge build-all <project>`
   - build 출력 예: `{"ok":true,"cmd":"build","id":"rogue","pass":true,"score":0.91,"failed":[],"cached":false,"out":"out/rogue"}`
   - QA 불합격: exit 2, `failed`에 id 목록, pack 생략

## 핵심 테스트
- 일부러 규칙을 어긴 래스터(팔레트 밖, 반투명, 고립 픽셀, 예산 초과)마다 해당 검사 실패 확인
- 같은 Spec 2회 build → 두 번째 `cached:true`, 출력 바이트 동일
- Spec 한 글자 수정 → 캐시 미스

## 범위 밖
애니메이션, 패킹 포맷(pack은 P5에서 연결; 지금 build는 render+qa까지).

## 수락 기준
```
pnpm build && pnpm test -- --reporter=dot
pnpm forge build-all dungeon        # 샘플 3종 리포트 + 교차 검사
```
`out/<id>/sheet.png` 중 **실패가 가장 많은 1장만** Read → Spec 수정 → 재빌드. 이 루프 최대 3회.

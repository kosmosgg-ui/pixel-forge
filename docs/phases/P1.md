# P1 — core: 래스터·색·도형·PNG 입출력

## 목표
도트를 "올바르게" 찍는 최하층. 이후 모든 품질이 이 단계의 정확성에 달려 있다.

## 시작 전
- 예시 바이블 `data/bibles/sample-v0.bible.json`으로 개발·테스트한다. 코드에 바이블 id나 수치를 하드코딩하지 않는다(§1 범용 툴).

## 읽을 것
- ARCHITECTURE §3, §4, §5
- `data/rules/default.rules.json`의 `ramp`, `materialContrast`, `cleanup`

## 작업 순서 (파일 단위, 각 파일마다 테스트 작성 후 다음으로)
1. `core/src/raster.ts`: `createIndexed(w,h)`, `getPx/setPx`(경계 밖 무시), `blitInPlace(dst, src, x, y)`(0=투명 건너뜀), `flipX`, `scaleNearest(r, k)`, `equals`
2. `core/src/palette.ts`: `Palette` 생성, `addColor`(중복 시 기존 인덱스), 인덱스 0=투명 보장, `toRGBA(raster, palette): Uint8Array`
3. `core/src/color/oklab.ts`: sRGB↔OKLab↔OKLCh 변환 (왕복 오차 테스트 ≤ 1/255)
4. `core/src/color/ramp.ts`: `makeRamp(baseHex, steps, contrast, rules.ramp) → string[] (hex, dark→light)`
   - 색상 회전은 최단 각도로 목표 hue까지만, 색역 밖은 C만 이분 탐색(최대 20회), hex는 반올림 후 클램프 (§4)
   - 테스트: 단계 수, 명도 단조 증가, 밝은 쪽 hue가 warmHue 방향으로 이동, 어두운 쪽이 coolHue 방향, 모든 색이 유효 sRGB, makeRamp 2회 결과 동일
5. `core/src/color/bible-palette.ts`: 바이블 → `{ palette, ramps: Record<material, Ramp>, outlineIndex, fxIndices }` (결정론적 순서: 재질 키 정렬, 같은 hex는 인덱스 공유)
6. `core/src/shapes/line.ts`: Bresenham + `pixelPerfect`(L자 모서리 제거)
7. `core/src/shapes/ellipse.ts`(`{w,h}`), `rect.ts`(`{w,h,chamfer?}`), `capsule.ts`(`{len,w}`), `poly.ts`: `→ { mask: Uint8Array, w, h, ox, oy, normals?: Int8Array }` — 채움 도형은 바운딩 박스 기준(§5)
   - 회전 파라미터 `angleDeg`는 도형 파라미터에 적용 후 래스터화(해석적 회전)
8. `core/src/shapes/mask-grid.ts`: ASCII rows + legend 파싱 → 마스크·재질·shade
9. `core/src/shapes/rotsprite.ts`: mask 파츠 전용 회전(8배 최근접 확대 → 회전 → 8×8 블록 최빈값 축소)
10. `core/src/cleanup.ts`: `removeOrphansInPlace`, `mergeSmallClustersInPlace(zone, minCluster)`
11. `cli/src/io/png.ts`: pngjs로 RGBA 읽기/쓰기. 쓰기 옵션 고정: `deflateLevel: 9`, `filterType: 0`, `colorType: 6`(RGBA), 메타데이터 청크 없음 → 바이트 결정론
12. `cli` 명령 `forge palette <bible>` → `out/palette/<bible>.png`(재질별 램프 행, 4배 확대)

## 핵심 테스트 (반드시 포함)
- 폭 1~16 원(`w = h`)이 상하좌우 대칭, 모든 픽셀 4-연결
- w=6 원이 좌우 대칭이고 폭이 정확히 6px
- 대각선 1px 선에 L자 모서리 0개
- 회전 0°/90°/180° 캡슐이 회전 전과 픽셀 수 동일
- `toRGBA` 결과 알파가 0 또는 255만
- 같은 래스터 PNG 쓰기 2회 → SHA-256 동일

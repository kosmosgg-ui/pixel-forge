# P5 — 패킹·익스포트 + 데모 연동(어댑터) + 핫리로드

## 목표
QA 통과 산출물을 웹 데모가 **코드 수정 최소로** 읽게 하고, Spec 수정 → 데모 화면 반영을 자동화한다.

## 읽을 것
- ARCHITECTURE §10, §11(pack/apply)
- `docs/demo-probe.md` (P0 결과)

## 작업 순서
1. `export/src/pack-shelf.ts`: shelf 패킹, 패딩 1px, 결정론적 순서
2. `export/src/format-aseprite.ts`: Aseprite 호환 JSON(hash) + frameTags + duration
3. `export/src/manifest.ts`: §10 manifest
4. `cli`: `forge pack`, build에 pack 연결(QA 통과 시에만)
5. `cli/src/adapters/<demo>.ts`: demo-probe 결과에 맞춘 어댑터
   - 산출물을 데모의 **별도 폴더**(예: `assets/forge/`)에 복사. 기존 스프라이트(Pixel Lab 제작분) 덮어쓰기 금지
   - 데모가 시트 JSON을 못 읽으면: 데모 쪽에 **로더 1파일만 추가**하는 패치를 제안서(`docs/demo-patch.md`)로 작성 → 사용자 승인 후 적용
   - 캐릭터별 소스 전환 토글(기존 / forge) 방식 제안
6. `cli`: `forge watch <project>` (chokidar) — Spec·바이블·anims 변경 시 해당 캐릭터만 build → apply

## 핵심 테스트
- 패킹 결과 프레임 겹침 0, 시트 크기 결정론
- Aseprite JSON의 frameTags 범위가 애니메이션 프레임 수와 일치
- apply 대상 폴더 밖 파일 변경 0 (임시 디렉터리로 테스트)

## 범위 밖
Godot 포맷(사용자 지시 전 금지), 노멀맵.

## 수락 기준
```
pnpm build && pnpm test -- --reporter=dot
pnpm forge build data/specs/dungeon/rogue.spec.json
pnpm forge apply data/specs/dungeon/rogue.spec.json --target <demo>
```
사용자에게 데모에서 확인할 방법(경로·토글)을 3줄로 보고.

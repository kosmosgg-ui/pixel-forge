# P5 — 패킹·익스포트 + 게임 연동(어댑터) + 핫리로드

## 목표
QA 통과 산출물을 **어떤 게임 엔진이든** 바로 읽을 수 있는 표준 형식(시트 PNG + Aseprite 호환 JSON + manifest)으로 내보내고, Spec 수정 → 게임 폴더 반영을 자동화한다.

## 읽을 것
- ARCHITECTURE §10, §11(pack/apply)

## 작업 순서
1. `export/src/pack-shelf.ts`: shelf 패킹, 패딩 1px, 결정론적 순서
2. `export/src/format-aseprite.ts`: Aseprite 호환 JSON(hash) + frameTags + duration — 대부분의 엔진·프레임워크가 이 형식을 읽는다
3. `export/src/manifest.ts`: §10 manifest
4. `cli`: `forge pack`, build에 pack 연결(QA 통과 시에만)
5. `cli/src/adapters/dir.ts`: 기본 어댑터 `dir` — `--out <dir>`(또는 바이블의 `apply.out`)에 `<id>/` 폴더째 복사
   - 대상 폴더 밖은 쓰지 않는다. 같은 이름 파일이 forge가 만든 것이 아니면 덮어쓰지 않고 exit 1
   - 어댑터 인터페이스(`Adapter { id, apply(artifacts, options) }`)로 분리해, 엔진별 어댑터는 나중에 파일 하나로 추가 가능하게
6. `docs/integration.md`: 엔진 무관 사용법 — 시트 JSON 구조 설명 + 순수 JS(Canvas 2D) 로더 예시 1개(40줄 이내)
7. `cli`: `forge watch <project>` (chokidar) — Spec·바이블·anims 변경 시 해당 캐릭터만 build → apply

## 핵심 테스트
- 패킹 결과 프레임 겹침 0, 시트 크기 결정론
- Aseprite JSON의 frameTags 범위가 애니메이션 프레임 수와 일치
- apply 대상 폴더 밖 파일 변경 0, forge가 만들지 않은 파일 덮어쓰기 0 (임시 디렉터리로 테스트)

## 범위 밖
엔진 전용 포맷(Godot 등, 사용자 지시 전 금지), 노멀맵.

## 수락 기준
```
pnpm build && pnpm test -- --reporter=dot
pnpm forge build data/specs/sample/rogue.spec.json
pnpm forge apply data/specs/sample/rogue.spec.json --target dir --out out/apply-test
```
사용자에게 산출물 경로와 integration.md 로더 예시 위치를 3줄로 보고.

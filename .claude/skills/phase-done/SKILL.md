---

현재 Phase를 아래 순서로 마무리한다. 각 단계 결과만 짧게 확인하고 넘어간다.

1. **수락 기준**: `test-runner` 서브에이전트에 해당 Phase 문서의 수락 기준 명령을 그대로 전달. FAIL이면 고치고 1부터 다시.
2. **독립 코드 검토**: `code-reviewer` 서브에이전트에 이번 Phase 시작 커밋을 기준으로 검토 요청. "높음" 항목은 반드시 수정, "중간"은 수정 또는 backlog 기록, "낮음"은 무시 가능.
3. **시각 검수** (렌더 결과가 있는 Phase만): `art-judge` 서브에이전트에 이번 Phase의 대표 결과 시트(`forge lineup`으로 보정 세트 v2 4장 + 대상)를 주고 등급 판정. 보정 확인이 무효면 1회만 다시, 같은 세트로 무효 2회면 판정자 순서·이유를 그대로 보고(유도 재시도 금지).
4. **기록**: `docs/progress.md`에 이 Phase 로그(10줄 이내)와 `현재 단계`를 다음 Phase로 갱신.
5. **커밋**: `P{n}: <요약>` + 검토에서 생긴 수정은 같은 커밋 또는 `P{n} 보정:` 커밋.
6. **보고**: report-doc 스킬 형식대로 「pixel-forge 작업 보고」 문서 갱신(15줄 이내). 결과 섹션에 art-judge 등급 한 줄 포함.
7. 사용자에게 링크와 3블록 보고(10줄 이내). 통과 주장에는 실행한 명령과 결과 요약 줄(예: `Tests 145 passed`)을 붙인다.
